# AgentQuant 最新回测亏损归因报告

## 1. 报告结论

本次回测收益率为负，核心原因不是系统算错账，也不是手续费或滑点单独导致，而是策略信号质量仍然不足：系统在多个品种上仍然允许“分析师信号冲突、市场确认偏弱、历史归因较差”的交易进入实盘执行链路。auditor 已经起到了压仓和拦截作用，但当前更多是把弱信号从大仓位降为小仓位，并没有把主要亏损组合彻底挡在交易之外。

一句话概括：亏损来自“弱信号仍然成交”，且亏损集中在少数品种、方向和信号组合上。

## 2. 回测基本结果

本次回测区间为 2025-01-06 至 2025-02-28，共 34 个交易日。

关键结果如下：

| 指标 | 数值 |
|---|---:|
| 初始资金 | 5,000,000.00 |
| 期末权益 | 4,968,879.49 |
| 总收益率 | -0.62% |
| 年化收益率 | -4.52% |
| Sharpe | -8.18 |
| 最大回撤 | 0.61% |
| 日结算 PnL | -30,165.00 |
| 手续费 | -955.51 |
| 完成交易数 | 75 |
| 交易胜率 | 45.33% |
| 完成交易归因 PnL | -24,504.19 |

收益率计算可以对上：

```text
(4,968,879.49 - 5,000,000.00) / 5,000,000.00 = -0.62%
```

因此，本次负收益不是评估模块把账算错，而是交易结果本身为负。

这里有两个关键现象：

第一，P 和 RB 不是单纯做错某一个方向，而是多空两侧都表现差。这说明问题不是简单的“多头看错”或“空头看错”，而是该品种当前的信号切换、趋势确认和入退场机制整体不稳定。

第二，C 多头、SR 多头这类方向胜率不低，但总 PnL 仍然为负，说明系统存在盈亏比问题：盈利单偏小，亏损单偏大。

这表明当前信号融合机制还不够严格。对冲突组合，系统只是降低仓位或依赖后续 intraday gate，而不是在策略生成阶段直接判定“不交易”。

## 6. auditor 的作用与不足

归因诊断显示：

| 项目 | 数值 |
|---|---:|
| 策略推荐数 | 510 |
| 有市场确认的推荐数 | 504 |
| 平均市场确认分数 | 0.5043 |
| auditor block | 311 |
| auditor reduce | 156 |
| auditor hold | 30 |
| auditor allow | 7 |
| no-trade 中由 auditor block 导致 | 269 |
| intraday trigger 未满足 | 26 |

auditor 已经明显启用，也拦截了大量交易。但是，完成交易归因里，75 笔完成交易全部来自 `trade_auditor_decision = reduce`。

这说明当前 auditor 的主要效果是“缩仓”，而不是“硬过滤”。它可以降低亏损幅度，但无法阻止弱信号造成持续小亏或少数大亏。

因此，当前亏损的核心机制是：

```text
信号冲突或市场确认不足
-> auditor reduce
-> 小仓位仍然成交
-> 若方向错误或盈亏比不佳
-> 累积为负收益
```

## 7. 高频执行并非亏损主因

成交记录显示，系统已经使用高频数据进行执行定价：

| 执行价格来源 | 笔数 |
|---|---:|
| intraday_first_valid_1m_open | 70 |
| intraday_next_1m_open | 56 |

交易成本如下：

| 成本项 | 数值 |
|---|---:|
| 手续费 | 955.51 |
| 估算滑点金额 | 5,225.00 |

手续费和滑点会拖累收益，但不是主因。即使不考虑手续费，日结算 PnL 仍然是明显负值。高频数据目前主要解决的是“成交价格更接近真实交易”，不是自动产生 alpha。

换句话说，系统已经更像可复刻的模拟盘/实盘执行框架，但交易信号本身仍需优化。

## 8. 数据质量是次要但真实的拖累

归因诊断显示，市场确认特征覆盖并不完全：

| 市场确认特征 | 可用次数 |
|---|---:|
| basis | 504 |
| variety_position_rank | 504 |
| symbol_position_rank | 504 |
| ls_ratio | 504 |
| broker_net_margin_change | 504 |
| broker_variety_profit | 504 |

其中 `net_flow` 缺失较多。日志中也持续出现 PandaAI 数据质量告警，包括部分品种资金流特征缺失、部分基本面指标 near-stale。

这些问题未必单独造成亏损，但会削弱 auditor 的市场状态识别能力，使市场确认分数和冲突判断更噪声化。

## 9. 核心亏损原因排序

按重要性排序，本次策略亏损的核心原因是：

1. 弱信号仍然进入交易链路。auditor 多数情况下只是 reduce，而不是对低质量组合硬 block。
2. 亏损高度集中在 P、RB、EB、HC、SR、J 等品种，说明品种差异化规则还不够。
3. 分析师信号冲突时，系统仍然交易，尤其 commodity_news 与 technical/fundamental 相反时亏损明显。
4. 盈亏比不佳。部分方向胜率不低，但亏损单幅度大于盈利单。
5. 高频数据只改善了执行价格，并没有改善日频方向判断。
6. 市场确认数据存在缺口，尤其 `net_flow` 缺失较多，影响 auditor 对市场状态的判断。

## 10. 后续优化方向

在下一轮 20 个交易日小规模回测前，最应该优先做三类优化：

1. 将 auditor 从“缩仓器”升级为“硬过滤器”：对历史归因明显亏损的品种方向和信号组合，直接禁止新开仓。
2. 对 P、RB、EB、HC 等亏损集中品种设置更严格的开仓门槛；对 BU、I 这类正贡献品种保留较正常的交易权限。
3. 对分析师冲突组合提高惩罚力度：当 technical、fundamental、commodity_news 方向明显冲突，且市场确认分数不足时，不再允许 reduce 后成交，而是直接 hold/block。

最终判断：当前系统运行链路已经基本通顺，亏损不是工程失败，而是策略层面的 alpha 质量和风控过滤还没有达到足够强度。
