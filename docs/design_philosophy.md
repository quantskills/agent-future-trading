# AgentQuant Design Philosophy

更新日期：2026-05-24

本文档是 AgentQuant 后续优化和修改计划的方向护栏。每次修改代码、配置或验收清单前，都应先对齐这里的设计初衷，避免把优化范围扩大成无关重构，也避免把资金利用率、学习能力或回测绩效目标理解错。

## 1. 系统定位与智能体边界

AgentQuant 本质上是一个多智能体期货交易策略生成系统，自带策略回测与模拟盘功能。它不是单一脚本、单一模型或单一信号源，而是一套由多个智能体按设计好的工作流协作生成日频期货交易策略，并直接进入回测或模拟交易的系统。

各智能体必须明确自己的工作边界：

1. 分析师负责在各自信息域内生成结构化交易证据和方向判断，不能越权决定成交、结算或硬风控。
2. Portfolio Manager 负责综合各类信号、学习记忆、市场确认和组合约束，生成可执行的日频策略目标。
3. Trade Auditor 负责确定性审计和风险分层，放过真正该放过的机会，拦住硬风险和成熟弱模板。
4. Trader 负责按盘前策略和当时可见盘中数据执行，不应临时创造新的策略观点。
5. Accountant 负责日终结算、保证金、手续费、持仓和账户权益，不应被分析文本覆盖。
6. Reviewer 负责复盘、归因、学习写回和验收诊断，不能用事后结果污染当天决策。

这些智能体既要独立工作，又要按固定流程协作。任何优化都应增强这种分工协作，而不是让某个智能体越权、让 LLM 自由改写交易系统，或让回测路径和模拟盘路径分叉。

## 2. LLM 调用边界与目的

AgentQuant 允许部分智能体调用 LLM，但 LLM 在系统中的角色必须被清晰限定：LLM 负责理解、归纳、解释和生成结构化候选判断；硬风控、成交、结算、保证金、手续费、数据库写回和最终审计必须由确定性代码与可追踪规则约束。

当前系统中直接调用 LLM 的智能体及目的如下：

1. Planner 调用 LLM 的目的，是在固定工作流和允许的分析师集合内辅助选择需要参与的分析师组合。它只能影响“让哪些分析师参与分析”，不能绕过系统既定 phase，也不能直接生成交易或资金指令。
2. Technical Analyst 调用 LLM 的目的，是把价格、成交量、波动率、趋势、支撑阻力、ATR、盘中/日频技术上下文整理成结构化技术面信号。它应输出方向、置信度、关键价位、失效条件、风险标记和可交易性说明，不能直接决定成交手数。
3. Fundamental Analyst 调用 LLM 的目的，是把供需、库存、仓单、基差、利润、资金流、产业链位置、数据新鲜度等基本面证据整理成结构化基本面信号。数据滞后或证据不足时，应给出可追责 Neutral，而不是强行给方向。
4. Commodity News Analyst 调用 LLM 的目的，是把商品新闻、事件类型、影响窗口、方向锚、可信度和是否已被价格消化等内容整理成结构化事件信号。新闻只能成为证据之一，不能单独覆盖市场确认、风控和执行门槛。
5. Macroeconomic / Policy Analyst 调用 LLM 的目的，是把宏观与政策信息转化为对相关期货品类的背景约束或方向倾向。它们提供的是环境判断和风险提示，不应直接替代品种级交易证据。
6. Portfolio Manager 调用 LLM 的目的，是在分析师信号、学习记忆、市场确认、组合风险和资金约束之上，生成结构化组合建议和风险解释。PM 的 LLM 输出必须再经过资金硬闸、Trade Auditor、Trader 执行门槛和会计约束校验。
7. Reviewer 可以按配置调用 LLM 做因果复盘候选总结，目的是帮助归纳交易成败、未成交原因、中性信号责任和可验证规则候选。Reviewer 的 LLM 结论不能直接污染当天决策，只能作为后续交易日的候选学习输入，并且必须经过样本验证后才可影响交易权限。

当前系统中不应依赖 LLM 做最终裁决的智能体包括：

1. Trade Auditor：负责确定性交易审计和风险分层，可以读取 LLM 产生的结构化信号，但最终 block、scale_down、probe_only、allow 等动作必须可由规则、证据和审计日志解释。
2. Trader：负责按盘前策略和当时可见盘中数据执行，不能临时调用 LLM 创造新策略观点，也不能用 LLM 改写成交价、成交手数或入场时间。
3. Accountant：负责日终结算、手续费、保证金、持仓、权益和 PnL，对账结果必须由交易记录和行情结算数据确定，不能由 LLM 解释覆盖。

因此，每次新增或修改 LLM 调用时，都必须满足三个条件：输出结构化、可审计、可被确定性规则约束。LLM 可以提升分析质量和复盘深度，但不能成为不可解释的自由决策器。

## 3. 资金设计初衷

资金利用率的目标不是“为了满仓而满仓”，而是把经过交易记录和市场证据反复验证的 alpha 机会适当放大。

核心原则：

1. 组合可交易资金/保证金占用最高为本金或账户权益的 20%，这是硬门槛。
2. 不硬性规定单品种固定资金占比。单个品种能用多少资金，应由机会质量、学习证据、市场确认、止损保护、剩余组合容量和当日风险状态共同决定。
3. 未经过验证的机会只能小额试探；多日交易或模拟盘证明有效的机会，才可以逐步获得更高预算。
4. 如果多个品种同时高质量，资金应在它们之间动态分配；如果只有一个品种特别强，也可以给它较大预算，但不能 all-in，仍要保留部分资金给其它机会和风险缓冲。
5. 单品种止损、失效价、ATR 距离、回撤控制和日终结算必须真实生效。提高资金利用率必须和退出机制一起设计。

因此，`max_single_position_ratio` 这类参数只能被理解为冷启动或弱信号下的基础 sizing anchor，不能被当成僵硬的单品种硬上限。真正的硬上限只有组合层面的 20% 主动资金/保证金门槛。

## 4. 学习回路设计初衷

引入智能体学习机制，不是为了让系统更会解释过去，而是为了让过去的交易记录真正影响下一轮的分析、决策、执行、结算、复盘和再调整。

日频分析不等于日频交易。AgentQuant 每个交易日前都要重新分析，但重新分析的结果可以是继续持有、观察、加仓、减仓、止损或平仓；不能把“每天生成策略”机械理解成“每天必须交易”。趋势已经被验证且同向证据仍成立时，系统应允许跨日持有和受控加仓；只有当失效位、止损、反向证据、持仓生命周期或组合风险真正触发时，才应退出或降低仓位。

围绕这一点，交易策略设计还有三条必须长期遵守的底层逻辑：

1. 每日盘前分析的意义是重新校验证据，而不是机械制造交易。分析师看准的趋势可以被继续持有，也可以在新证据继续支持时受控加仓；如果只是因为进入了新交易日就反复开平仓，系统会更容易错过真正的中长期价格趋势。
2. 系统不应硬性压制或硬性释放某个期货品类。品种、方向和模板只能通过真实信号、市场确认、历史学习结果、当前持仓状态和风险预算动态形成交易策略；不能为了修复某个短窗口回测表现，把品种写成固定黑名单、白名单或方向特例。
3. 浅样本不能成为放大仓位的充分理由。一次或少数几次正确只能说明值得继续观察或小仓验证，不能直接升级成高置信重仓；必须经过多日、多样本、胜率、净收益、回撤、市场确认和反证条件的重复检验后，才允许逐步扩大资金投入。

因此，Portfolio Manager、Trade Auditor、Trader 和 Reviewer 的配合关系应体现为：PM 负责把学习证据转化为候选仓位意图，Auditor 负责挡住浅样本乐观和硬风险，Trader 负责只在当时可见盘中条件满足时执行，Reviewer 负责在结算后把真实结果写回下一轮学习。学习闭环越强，越要防止它变成自我强化的乐观闭环。

学习应落实到以下环节：

1. 分析师读取与自己时间维度、品种维度相匹配的历史摘要。
2. Portfolio Manager 根据 template、ticker、side、horizon、sector、market regime 的历史表现调整资金释放。
3. Trade Auditor 对成熟弱模板、冷启动模板、protected/deployable 模板做不同处理。
4. Trader 根据已验证机会和盘中可见数据决定是否执行，而不是机械照搬盘前建议。
5. Reviewer 把交易结果、未交易原因、中性信号责任和会计结果写回可验证的学习状态。

学习要有深度：不能只把所有品种、所有周期、所有分析师混成一个粗糙平均经验。技术面、基本面、商品新闻对不同品种和不同持仓周期的适用性不同，学习记忆必须保留这些差异。

学习也要有克制：不能因为短窗口盈利就盲目放大，也不能因为短窗口亏损就把某个品种永久打入黑名单。学习结果必须经过样本数、胜率、净收益、市场确认和反证条件共同验证。

## 5. 提高信号质量与扩大 Alpha

扩大 alpha 收益的前提是交易信号质量真正提高，而不是简单扩大仓位。

分析师输出应逐步从泛泛的 Bullish、Bearish、Neutral，升级为可验证的业务证据：

1. 技术面要说明趋势阶段、关键价位、波动率、入场条件、失效位和 ATR 风险。
2. 基本面要说明供需、库存、仓单、基差、利润、资金流、产业链位置和数据新鲜度。
3. 商品新闻要说明事件类型、影响窗口、方向锚、可信度和是否已经被价格消化。
4. Neutral 信号必须可追责：是证据不足、冲突太强、风险规避合理，还是分析师过度保守。

只有当高质量信号经过交易记录验证，并且当日市场确认与执行条件支持时，系统才应逐步提高资金利用率。否则，低仓位本身不是错误；它可能是在等待真正的 alpha。

## 6. 重仓必须经过谨慎论证

系统允许对“看得准”的机会重仓，但重仓必须满足更高门槛。

重仓前至少需要检查：

1. 是否已有足够历史样本，而不是一两笔交易的偶然收益。
2. 胜率、净收益、回撤和盈亏比是否支持该模板或方向。
3. 当前 market confirmation 是否支持，而不是只依赖旧记忆。
4. 是否存在同 ticker-side 或 signal combo 的 weak/watchlist 冲突记忆。
5. 是否有明确止损、失效价或退出机制。
6. 组合 20% 总硬闸、净敞口、可用保证金和账户回撤是否允许。
7. protected、deployable 或 adaptive protect 结论是否来自足够样本，而不是短期偶然盈利或单日归因。

浅样本 protected/deployable/adaptive protect 只能代表候选观察或小仓验证资格，不等于重仓许可。审计员负责在盘前挡住过度乐观，复盘者负责在结算后用更多样本验证这些结论是否真的可靠。

强机会扩仓必须有建仓前已经形成的风险失效边界。`invalidation_level` 应来自 Phase1 盘前可见的历史价格结构，例如前低/前高、支撑阻力、突破位回踩失守、关键均线或趋势结构失效位；`atr_stop_distance` 应来自 T-1 及以前价格波动率计算出的 ATR 止损距离。它们的含义是：“如果今天按这个逻辑建仓，那么根据昨天以前已经可见的价格结构，我错了的位置在哪里。”

Reviewer 可以在复盘中总结“某类 ticker-side-signal_combo 未来必须带止损/失效边界才允许加仓”的规则，但不能给已经发生的交易事后补一个止损价来证明当时可以重仓。复盘学到的是未来规则；下一次交易日前，分析师必须基于当时可见数据重新生成当日可执行的 `invalidation_level` 或 `atr_stop_distance`。如果生成不出来，即使历史学习结果是 protected/deployable，也只能按普通确认机会或小仓试探处理，不能进入 16%-20% 强机会资金带。

重仓不是奖励“自信”，而是奖励“被验证过且当前仍成立的高质量机会”。

## 7. 防止过拟合与未来信息污染

任何优化都不能为了修复某个短窗口亏损，直接写死品种黑名单、方向白名单、日期特例或未来结果。

必须遵守：

1. Phase1 只能使用交易日前已经可见的信息。
2. Trader 只能使用当时已经形成的盘中数据，不能用收盘后结果反推入场。
3. Phase3 结算结果只能进入当日结算和下一期学习，不能影响当天盘前决策。
4. Reviewer 可以总结当天结果，但只能作为未来交易日的受控学习输入。
5. LLM 可用于分析、解释和候选因果总结，不能直接改写硬风控、成交价、成交手数或会计结果。

回测中能用的信息，必须是在模拟盘或真实交易中同一时点也能拿到的信息。否则该策略不可复刻。

## 8. 回测、模拟盘与实盘一比一复刻

AgentQuant 的回测不是孤立研究脚本，而是模拟盘和未来实盘流程的历史回放。

因此：

1. 回测、模拟盘和真实交易应共享同一套 Phase1、Trader、Accountant、Reviewer 逻辑。
2. 交易建议、盘中执行、手续费、保证金、逐日盯市、平仓盈亏和学习写回都必须可审计。
3. 任何“只在回测中成立”的捷径都不能进入主线。
4. 如果某项数据在真实交易时无法按同样 cutoff 获得，就不能用于当下决策。
5. 日终结算和账户权益变化必须以会计师/settlement 结果为准，而不是只看已平仓配对归因。
6. Phase3 日终财务结算必须使用交易当日官方结算价、真实手续费、真实保证金规则和实际持仓；不得为了让回测不断而用成交价、上一日结算价、估算价或事后补价替代当天官方结算价。若当天官方结算价暂时取不到，正确做法是缓存、重试、修复数据链路后重跑该日，而不是伪造会计结果。

优化的目标不是让历史曲线看起来更漂亮，而是让同一套策略在未来模拟盘或实盘中能按同样规则执行。

## 9. 学得要深，但不能盲目乐观

系统应该真正学习，但不能变成过度乐观的自我强化系统。

健康的学习状态应该表现为：

1. 强模板被逐步释放资金，弱模板被 cap、probe 或 block。
2. learned 与 unlearned 样本能被清晰区分，并能比较胜率、PnL 和回撤。
3. 中性信号追责能减少无责任 Neutral，而不是鼓励乱给方向。
4. 分析师的品种、板块、时间维度适配越来越清晰。
5. 资金利用率从低位逐步向 16%-20% 推进，但只在高质量机会足够时发生。
6. 如果结果变差，系统能定位是信号质量、执行门槛、数据缺口、资金预算、风控还是市场环境问题。

不健康的学习状态包括：

1. 所有交易都被标成 learned，导致无法比较。
2. 一次短期盈利就大幅提高仓位。
3. 为了提高资金利用率而放大弱信号。
4. 反复亏损后只靠解释文本自圆其说，不改变下一轮交易权限。
5. 用未来复盘结论污染历史决策。

## 10. 修改系统时的边界

后续每次优化都应先问：

1. 这个修改是否服务于资金利用率、alpha、信号质量、学习深度、无未来函数或实盘可复刻？
2. 它是否只针对短窗口结果过拟合？
3. 它是否会让回测和模拟盘/实盘逻辑分叉？
4. 它是否会绕过 20% 组合硬闸、会计结算或确定性风控？
5. 它是否让学习结果真正影响下一轮决策，而不是只增加解释文本？
6. 它是否保留品种、板块、分析师、horizon 和 market regime 的差异？

如果答案不清楚，应先补验收项和诊断输出，而不是急着扩大修改范围。

## 11. 数据库与 Artifact 边界

AgentQuant 保留 `src/assets/agentquant.db` 作为唯一运行主库。所有回测、模拟盘、智能体学习、复盘写回和评估逻辑，都只能把这个主库视为运行事实来源；不得把运行状态拆到多个互相竞争的 SQLite 主库里，也不得让可选查看库反向参与智能体决策。

`agentquant.db` 应保存的是结构化、可索引、会被系统学习或审计继续使用的内容：

1. `config`、`portfolio`、`trading_day_phase` 等实验、账户和流程状态。
2. `futures_transactions`、`daily_settlement`、`ticker_daily_pnl` 等账本、成交、保证金、手续费和 PnL 记录。
3. `futures_recommendation` 和 `futures_transactions` 的关键字段、状态、动作、手数、价格、warning、短摘要，以及 `signal_snapshot`、`audit_payload`、交易审计 prompt 的 artifact 路径、checksum、大小和摘要。
4. `strategy_memory`、`adaptive_policy_state`、`capital_deployment_state`、`config_learning_overlay`、`signal_template_performance`、`analyst_performance` 等学习结论、标签、状态和参数覆盖。
5. neutral accountability、causal validation、Reviewer 学习报告索引、规则验证状态等结构化复盘结果。

不适合长期全量塞进主库的内容，应外置到 `src/logs/artifacts/` 或对应日志目录：完整日志文本、LLM 原始长 prompt / response、大段 analyst report 原文、完整 evidence pack、PandaAI 原始 payload、分钟线或大行情缓存、每日 summary 的完整 JSON 大对象、图片、报表和临时 debug artifact。主库只保存 `artifact_path`、`sha256`、`size`、`summary_json`、`trading_date`、`config_id`、artifact 类型和关键诊断字段。

这种边界不削弱学习机制。智能体学习真正需要的是“结论、标签、状态、索引和可验证摘要”，这些继续留在 `agentquant.db`；当 Reviewer、评估脚本或人工复盘确实需要完整上下文时，再通过主库中的 artifact 路径和 checksum 回读外置文件。换句话说，学习闭环读到的是同一份事实，只是不再把大文本和大 payload 塞在 SQLite 行里。

`src/assets/agentquantcheck.db` 只能是可选的轻量只读查看副本，用来给 SQLite Viewer 免费版查看资金流、每日营收、成交、推荐摘要和学习状态。它不是系统运行库，不被任何智能体读取，不承担学习写回，也不能作为回测或模拟盘事实来源。需要查看时，可由 `python database/build_check_db.py` 从主库重建；主库和 artifact 文件仍是唯一可复刻、可审计的完整来源。
## 12. 回撤保护与恢复交易原则

AgentQuant 的回撤控制必须保护本金，但不能把系统变成永久停摆。账户权益回撤采用三层状态：正常状态为回撤低于 4%，警戒状态为 4%-5%，硬保护状态为 5% 及以上。5% 是账户级硬保护弱参，可以在配置文件中调整；它不是单品种止损，单品种仍然由失效价、ATR stop、持仓生命周期、换约和 ticker loss 控制处理。

警戒状态不是停止交易，而是降低新开仓和加仓的风险预算。此时系统仍允许平仓、减仓、换约、止损，也允许被充分确认的小额机会；但普通机会不应主动冲 6%-8% 资金利用率，强机会也不能直接进入 16%-20% 总保证金资金带。

硬保护状态不是简单 reduce-only。第一次进入硬保护后，系统先完整冷静 1 个交易日，不开新的增量风险，但各智能体仍然正常分析、复盘、更新记忆并记录 shadow recommendation。冷静期后，只有满足更高门槛的机会才能做 1%-2% 总保证金预算内的恢复试探：方向要清楚，PandaAI 或市场确认要支持，Trade Auditor 不能硬拦，不能是近期弱模板的盲目释放，并且必须有当日盘前可见数据生成的 invalidation_level 或 atr_stop_distance。

如果恢复试探继续亏损，系统进入更长冷静期：第一次试探亏损后暂停新开仓 2 个交易日，第二次试探亏损后暂停 3 个交易日并进入只观察模式，之后每再亏一次就增加 1 个交易日冷静期。冷静期不是摆烂，分析师、PM、Auditor、Trader、Accountant 和 Reviewer 仍按原工作流运行，记录“如果交易会怎样”的 shadow recommendation，用于未来学习，但不把它变成真实新开仓。

恢复正常必须有条件，而不是冷静期结束就自动乐观。只有当恢复试探开始连续盈利，近期真实交易和 shadow recommendation 不再继续恶化，没有新的止损或连续亏损，Reviewer/Auditor 未提示过度乐观，并且账户回撤重新低于 4% 时，系统才回到正常状态。恢复顺序应从 1%-2% 小额试探，逐步走向 2%-4%、4%-6%、6%-8% 的普通确认机会资金带；16%-20% 的强机会总保证金上限只能在正常状态下、经过充分学习验证和止损边界确认后使用。
